# SecureShop Security Coverage Matrix

| Vulnerability | Attack Scenario | Affected Routes/Features | Root Cause | Defense | Code Location | Test | Evidence | Status |
|---|---|---|---|---|---|---|---|---|
| **SQL Injection (SQLi)** | Attacker submits `' OR '1'='1` or SQL comment payloads (`alice' --`) into login or search to bypass authentication or extract sensitive data. | `/login`, `/products`, `/product/<id>`, `/checkout`, `/admin` | Dynamic string interpolation or unparameterized queries in SQL execution. | Parameterized queries with `?` placeholders across all database queries; hardcoded allowlist query map for administrative statistics. | `app.py:db`, `app.py:products`, `app.py:login`, `app.py:admin` (`# [SECURITY-DEFENSE: SQL Injection Prevention]`) | `test_sqli_login_bypass_attempt`, `test_sqli_product_search`, `test_catalog_search_and_empty_state` | Login fails with `Invalid credentials`; search returns safe empty result; union queries blocked. | **DEFENDED** |
| **Cross-Site Scripting (XSS)** | Attacker inputs `<script>` tags or malicious event handlers (`<img onerror=...>`) in product reviews or search parameters. | `/product/<id>/review`, `/products`, Jinja2 templates | Rendering unsanitized user content with `|safe` or missing context-aware output encoding. | Jinja2 autoescaping preserved globally without `|safe` on user input; Content-Security-Policy header restricting script execution; input length and pattern validation. | `app.py:review`, `app.py:set_security_headers`, `templates/product.html`, `templates/products.html` (`# [SECURITY-DEFENSE: XSS Prevention]`) | `test_stored_xss_product_review`, `test_reflected_xss_search_query` | Review body and search query strings are safely HTML-entity escaped (`&lt;script&gt;`). | **DEFENDED** |
| **Cross-Site Request Forgery (CSRF)** | Third-party malicious website submits unauthorized state-changing POST requests (e.g., checkout, profile update, admin user demotion). | All state-changing routes: `/login`, `/logout`, `/register`, `/verify`, `/profile`, `/cart/*`, `/checkout`, `/newsletter`, `/admin/*` | Missing anti-CSRF token verification on state-changing requests. | Global `before_request` handler enforcing constant-time `hmac.compare_digest` CSRF token verification on all POST/PUT/DELETE/PATCH operations. | `app.py:csrf_protection`, `templates/*.html` (`# [SECURITY-DEFENSE: CSRF Protection]`) | `test_csrf_missing_token_rejected`, `test_csrf_invalid_token_rejected`, `test_csrf_protects_all_state_changing_endpoints` | Missing or mismatched CSRF tokens are rejected immediately with HTTP 400. | **DEFENDED** |
| **Insecure Direct Object Reference (IDOR)** | Authenticated user manipulates order ID in `/orders/<order_id>` to view another customer's private order and receipt details. | `/orders/<int:order_id>` | Relying on client-supplied identifiers without comparing ownership against session identity. | Server-side ownership verification ensuring non-admin users can only query orders matching `user_id == current_user()["id"]`; returns 404 on unauthorized access. | `app.py:order_detail` (`# [SECURITY-DEFENSE: IDOR Prevention]`) | `test_idor_order_access_prevented`, `test_admin_can_view_any_order` | User Alice querying Bob's order receives HTTP 404; admin can view all orders. | **DEFENDED** |
| **Broken Access Control** | Unauthenticated users or non-admin customers access administrative dashboard and user management endpoints. | `/admin`, `/admin/users`, `/admin/products`, `/admin/coupons` | Missing role-based authorization gates on administrative views. | `@admin_required` decorator verifying that authenticated user has `role == 'admin'`, returning 403 Forbidden for non-admins and 302 to login for unauthenticated visitors. | `app.py:admin_required`, `app.py:login_required` (`# [SECURITY-DEFENSE: Broken Access Control Prevention]`) | `test_broken_access_control_admin_endpoints`, `test_access_controls_csrf_and_private_orders` | Unauthenticated requests redirect to `/login`; regular users receive HTTP 403 Forbidden. | **DEFENDED** |
| **Account Verification Bypass** | Attacker bypasses activation by guessing one-time codes, reusing previously consumed codes, or using expired codes. | `/register`, `/verify`, `/login` | Verification codes that do not expire, lack attempt limits, or remain valid after initial verification. | 5-attempt limit (`verification_attempts >= 5`), 30-minute expiration timestamp (`verification_code_expires_at`), code nullification upon successful use, and login gate enforcing `is_verified == 1`. | `app.py:register`, `app.py:verify`, `app.py:login` (`# [SECURITY-DEFENSE: Account Verification Bypass Prevention]`) | `test_unverified_user_cannot_login`, `test_verification_code_reuse_prevented`, `test_verification_code_guessing_throttling`, `test_expired_verification_code_rejected` | Unverified login redirects to `/verify`; second attempt with same code rejected; >5 failed guesses locks verification; expired codes rejected. | **DEFENDED** |
| **Privilege Escalation** | Attacker injects `role=admin` or `store_credit=99999` in registration form or profile edit request. | `/register`, `/profile`, `/admin/users/<id>` | Mass assignment vulnerability or accepting client-supplied role and credit fields. | Registration strictly hardcodes `role='user'` and `store_credit=500.0`; profile update strictly updates only username and email; admin user update prevents self-demotion. | `app.py:register`, `app.py:profile`, `app.py:admin_user_update` (`# [SECURITY-DEFENSE: Privilege Escalation Prevention]`) | `test_registration_privilege_escalation_prevented`, `test_profile_privilege_escalation_prevented`, `test_admin_cannot_demote_self` | Manipulated `role` or `store_credit` form fields are ignored; user remains regular user; self-demotion blocked. | **DEFENDED** |
| **Session Security & Session Hijacking** | Session fixation or cross-site cookie leaks allowing attacker to hijack authenticated sessions. | `/login`, `/logout`, Session cookie | Failure to regenerate session identifiers upon privilege level change and permissive cookie attributes. | `session.clear()` invoked upon login and logout; CSRF token regenerated; `SESSION_COOKIE_HTTPONLY=True`, `SESSION_COOKIE_SAMESITE='Lax'`, and `SESSION_COOKIE_SECURE` in production. | `app.py:login`, `app.py:logout`, `app.py:config` (`# [SECURITY-DEFENSE: Secure Session Management]`) | `test_session_regeneration_on_login`, `test_session_invalidation_on_logout` | Session data and CSRF tokens change upon login; session cleared on logout. | **DEFENDED** |
| **Brute Force & Credential Attacks** | Attacker automates password guessing against user accounts or verification codes. | `/login`, `/verify` | No rate limiting, account lockout, or request throttling. | Tracking `failed_attempts` with automatic 15-minute account lockout after 5 consecutive failures; IP rate limiter sliding window; generic error messages preventing user enumeration. | `app.py:login`, `app.py:check_ip_rate_limit`, `app.py:record_ip_attempt` (`# [SECURITY-DEFENSE: Brute Force Prevention]`) | `test_brute_force_account_lockout`, `test_generic_credential_error_prevents_enumeration` | 5 failed login attempts triggers temporary account lock; generic "Invalid credentials" error returned consistently. | **DEFENDED** |
| **Security Misconfiguration** | Information disclosure via stack traces, default debug mode, missing HTTP defense headers, clickjacking. | Global HTTP responses, error handlers | Missing security headers and verbose error handling in production. | Strict HTTP security headers (`nosniff`, `DENY`, `strict-origin-when-cross-origin`, CSP); custom error handlers for 400, 403, 404, 500 without stack traces; `debug=False`. | `app.py:set_security_headers`, `app.py:bad_request`, `app.py:internal_error` (`# [SECURITY-DEFENSE: Security Misconfiguration Prevention]`) | `test_security_headers_present`, `test_custom_error_handlers_do_not_leak_traces` | Headers present in all responses; error responses render clean UI with zero traceback disclosure. | **DEFENDED** |
| **Open Redirect** | Attacker crafts phishing links (`/login?next=https://evil.com` or `//evil.com` or `/\evil.com`) to redirect victims to malicious domains post-authentication. | `/login` (`next` parameter) | Blindly redirecting to user-supplied query string parameters. | `safe_redirect_url` validation rejecting absolute schemes, protocol-relative (`//`), backslashes (`/\`), and non-local paths, falling back to `/`. | `app.py:safe_redirect_url`, `app.py:login` (`# [SECURITY-DEFENSE: Open Redirect Prevention]`) | `test_open_redirect_mitigations` | Malicious redirect parameters are safely sanitized to `/`; safe relative paths allowed. | **DEFENDED** |
| **Sensitive Information Exposure** | Leaking password hashes, internal error traces, or sensitive user records in API responses or logs. | `/admin/users`, error pages, audit logs | Selecting sensitive fields (`password_hash`) in administrative views or logging credentials. | Password hashes excluded from queries in `/admin/users`; audit logs truncate details and exclude passwords; generic error pages. | `app.py:admin_users`, `app.py:audit`, `app.py:error handlers` (`# [SECURITY-DEFENSE: Sensitive Information Protection]`) | `test_admin_users_view_does_not_expose_password_hashes`, `test_custom_error_handlers_do_not_leak_traces` | Admin users HTML contains zero password hash strings (`pbkdf2:`, `scrypt:`); logs contain no secrets. | **DEFENDED** |
| **Business Logic Vulnerabilities** | Client manipulates prices, quantities (negative items), double-spends store credit, or races coupon redemption. | `/cart/*`, `/checkout`, `/admin/products` | Trusting client-side prices or totals; non-atomic multi-step order placement. | Server-side price calculation directly from DB; negative/zero quantity checks; `BEGIN IMMEDIATE` atomic transaction locking DB during checkout; atomic single-use coupon update. | `app.py:cart_update`, `app.py:checkout`, `app.py:product_values` (`# [SECURITY-DEFENSE: Business Logic Protection]`) | `test_client_cannot_manipulate_price`, `test_negative_cart_quantity_rejected`, `test_insufficient_store_credit_blocked`, `test_ineligible_coupon_rejected`, `test_single_use_coupon_can_only_discount_one_concurrent_order` | Client prices ignored; negative quantities rejected; insufficient credit blocked; concurrent coupon redemption race prevented. | **DEFENDED** |
| **File Security (Path Traversal)** | Attacker submits path traversal sequences (`../`, `..\\`) to download arbitrary system files. | `/download`, `/files` | Concatenating unvalidated user file names into filesystem paths. | `safe_file()` helper using `secure_filename()` and resolving canonical parent directory; returns 404 on directory escape attempts. | `app.py:safe_file`, `app.py:download`, `app.py:files` (`# [SECURITY-DEFENSE: File Security - Path Traversal Prevention]`) | `test_path_traversal_downloads_prevented`, `test_access_controls_csrf_and_private_orders` | Traversal requests return HTTP 404; private parent files cannot be read. | **DEFENDED** |
